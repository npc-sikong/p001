# 陪伴服务平台 两端产品架构建议稿

*产品规划建议  V1.3  2026年10月6日（V1.1：2026年9月9日）*

产品采用一个用户 App 和一个运营后台。App 内统一为用户身份，注册后默认拥有用户功能；申请并通过服务者认证后，在同一账号上增加服务者功能，同时保留原有用户功能及相应权益规则。个人中心通过“用户中心／服务者中心”切页展示功能，后台由平台总控和代理按岗位权限使用；账号、订单、消息、资金账务与审计共同复用。

产品定位为游戏陪玩、语音陪聊、学习陪伴的服务交易与社区平台。用户可浏览直购，也可通过 VIP 需求匹配选人。服务按单次、按天、按周商品下单：会员选择服务期和结算周期（每 1 / 3 / 7 天），下单时一次付清整个服务期的费用，由平台保管；每个结算周期结束后次日 00:00 自动结算给服务者。会员通过余额钱包（USDT 计价）充值和支付，推广分红与订单退款也进入余额钱包，可申请提现。

>
> 1. **新增会员余额钱包**（USDT 计价）：充值、余额支付、推广分红与订单退款入账、提现。V1.1 第 8 节“不增加供用户自由充值、转账的钱包”作废。见第 3、8 节。
> 2. **服务订单改为一次付清、周期结算**：会员选择服务期与结算周期，一次付清整个服务期，每个结算周期到期自动结算。V1.1 的“每期预付当期费用、按下一期主动续费”作废。见第 3、7 节。

## 1 两端与功能权限

| 产品端 | 功能或岗位入口 | 职责 |
| --- | --- | --- |
| 用户 App | 全部账号默认拥有用户功能 | 按原权益规则浏览商品、论坛互动、发布需求、购买服务、使用余额钱包（充值、支付、提现）、申请中止、确认履约、评价售后。 |
| 同一个用户 App | 服务者认证通过后增加服务者中心 | 保留全部用户功能，新增商品档期、应征接单、试聊履约、证据协作、收益结算与提现申请。 |

## 2 本次架构调整

第一，将原用户端和服务者端合并为统一用户 App。所有账号默认使用用户功能，通过认证后追加服务者能力；“我的”内部提供用户中心和服务者中心切页。原城市渠道端和中控端合并为运营后台的两个权限视图。订单按“我购买的服务”和“我提供的服务”分组，业务操作依据认证状态及本人在具体订单中的关系校验。

第二，建立主订单、服务期与周期账单、履约记录，分别管理一次付清的服务期费用、服务交付和按结算周期的服务者结算。增加中止申请：服务不达标时，会员可申请中止并退还尚未结算的费用；处理方式由后台设置，默认直接由平台处理，也可改为先由公会处理。

第三，将论坛与需求合并为一级导航“广场（需求与社区）”，连接服务消费与需求发布；“发现”用于按条件找服务者。首期延续原 VIP 发帖、回复和需求发布规则；普通用户仍可浏览和直接购买。

第四（V1.2 新增），为会员增加余额钱包。充值和支付以 USDT 计价；推广分红与订单退款进入钱包的可提现余额；充值本金只能消费。

## 3 用户 App 统一导航与用户功能

所有用户统一使用“首页、发现、广场、消息、我的”五个一级导航，通过服务者认证后也保持这套导航。订单中心置于“我的”，并在交易后、服务预约前和聊天页提供订单快捷入口。个人中心默认展示用户中心，服务者中心作为认证通过后增加的内部页面。

| 一级导航 | 主要页面与功能 |
| --- | --- |
| 首页 | 分类、搜索筛选、服务者列表、商品列表、商品详情；显示价格、次数或时长、档期、语言、规则与服务者资料。 |
| 发现 | 按游戏、语言、地区、价格与在线状态筛选服务者，进入服务者主页、试听、咨询与预约；立即找人。 |
| 广场 | 需求与社区：论坛推荐、最新、板块和话题、搜索、帖子详情、图文发帖、回复、点赞收藏关注、我的发布；结构化及匿名需求发布、审核进度、匹配进度、服务者候选、候选失效、无匹配和用户选人。 |
| 消息 | 订单会话、下单前咨询、通知与待办、房间邀请；文字、图片、语音消息；试聊及订单内一对一语音。 |
| 我的 | 用户中心包含个人资料、我的钱包（余额、充值、提现、资金明细）、我购买的服务、需求、帖子、月度 VIP、付款退款记录、评价、举报售后及设置；提供服务者申请或审核进度，认证通过后增加服务者中心切页。 |

### 账号与会员

统一注册登录与个人资料，支持国家、城市、语言、时区及 18+ 校验。每个账号默认是用户，服务者认证通过后追加相应功能；个人中心切页仅改变功能展示，账号身份、认证状态及权益不随切页变化。单一月度 VIP 支持发帖、回复以及结构化或匿名需求发布，服务者通过认证不自动获得 VIP。

### 商品与购买

首发保留游戏陪玩、语音陪聊、学习陪伴三类共 9 个商品模板，具体模板名称与规格另行落表。商品统一展示服务内容、价格、单次时长、可预约时间、下单规则，以及试聊、换人、取消、退款和服务中止规则。日、周商品应说明每期次数或时长、可选服务期和结算周期。

订单确认页展示服务者、所选规格、服务期与结算周期、服务区间与时区、一次付清的应付金额和付款方式。付款优先使用余额钱包，余额不足时引导充值，到账后返回继续支付。按会议记录，收付仅接 USD 数字货币（USDT），GCash 与银行卡不在当前收付范围。支付成功页进入预约或服务准备；支付失败、处理中和结果未知均可返回订单查询，结果未知时只查询原请求。

### 消费者完整主流程

浏览直购，或 VIP 发布需求并通过审核 → 匹配候选并选人 → 选择服务期与结算周期、确认订单并一次付清 → 试聊或申请换人 → 正式服务 → 每个结算周期到期自动结算（可提前确认完成）→ 评价与售后。

服务开始前可取消订单，全额退回余额钱包。开始后合作正常不能无故取消；服务不达标时可从订单详情申请中止，退还尚未结算的费用。服务期结束后如需继续，重新下单。

订单中心按待支付、待服务、服务中、待确认、已完成及售后等业务阶段组织列表。订单详情展示每个结算周期的金额与结算状态；支付、退款、暂停结算与出款信息单独展示，避免一个“完成”状态掩盖不同处理进度。

## 4 个人中心切页与服务者功能

“我的”顶部提供“用户中心／服务者中心”切页，服务者中心在申请审核通过后开放。切页后仍保留 App 原有的五个底部导航，不改变首页、发现、需求和消息的使用方式。工作台、商品、接单订单和收益等功能均放在服务者中心内部。

### 申请与开放状态

| 账号状态 | 个人中心展示 | 可用功能 |
| --- | --- | --- |
| 未申请 | 用户中心及“申请成为服务者”入口 | 原有用户功能，可提交入驻申请。 |
| 审核中或需补件 | 用户中心及审核进度、补件入口 | 原有用户功能，可查看进度和补充材料；暂不开通接单和商品上架。 |
| 审核未通过 | 用户中心及审核原因、重新提交入口 | 原有用户功能，可按规则整改后重新申请。 |
| 审核通过 | 用户中心与服务者中心切页 | 原有用户功能全部保留，并增加经认证授权的服务者功能。 |

### 服务者中心内部模块

| 内部模块 | 主要页面与功能 |
| --- | --- |
| 接单工作台 | 今日状态、待处理订单、公开需求及详情、提交应征、我的应征；预约提醒和服务异常提示。 |
| 商品与档期 | 商品列表、新建编辑、模板规格、价格、可预约时间、上下架及审核进度。 |
| 我提供的服务 | 待处理、服务中、已完成及售后订单；到场确认、试聊、正式服务、履约节点、中止申请的说明与异议、本人证据。 |
| 收益与结算 | 收益总览、按结算周期的收入与结算明细、待结算和暂停结算金额、可结算收入、提现申请、出款状态与失败处理提示。 |
| 服务资料与认证 | 实名 KYC、技能认证、培训协议、认证进度、服务介绍、认证信用和服务设置；基础账号资料沿用同一份。 |

### 统一账号与订单操作权限

服务者始终使用同一个用户账号，也可以购买其他服务者的服务、使用论坛和会员功能，并按对应订单规则确认服务、申请中止或售后。订单按“我购买的服务”和“我提供的服务”分组，通知标明订单及购买或接单事项。管理商品、应征、收益和提交证据时必须校验本人归属；禁止购买自己提供的服务或给自己评价。

账号、资料、语言与时区设置、聊天、通知和举报入口统一共用。订单聊天根据本人在具体订单中的关系展示购买方或服务方操作。对于本人提供的服务，只能提交自己的到场、试聊、履约和证据事实，无权直接确认该订单完成；对于本人购买的服务，可以正常行使购买方确认和售后权利。退款执行、放款及信用修改仍由平台授权岗位负责，切页不能绕过权限校验。

### 试聊与换人规则

保留试聊准备、试聊过程、继续服务、取消和换人。普通试聊权益为每个主订单最多一次成功换人；只有替换成功才扣额度，候选失效、无匹配或替换失败不扣额度。服务期内的多个周期账单不重置试聊或换人权益。正式服务中的换人进入异常履约或售后处理，重新核定前后服务者的履约区间与金额，不自动刷新试聊权益。

商品规则明确试聊时长、是否收费、未到场与超时处理，以及换人前后履约和收益如何拆分；不能把试聊默认计为付费服务。服务者提交完成摘要，消费者确认或依预先公示的规则进入下一阶段。

### 收益与提现入口

提现申请只针对可结算收益，仍受日或周批次、复核与可用资金条件约束。自动结算和手动提现共用同一可结算余额及金额占用记录，防止重复支付。服务者收益按收益结算与提现流程处理，不进入会员余额钱包。

会员申请中止后，服务者可以提交说明与图片材料，并可在处理结果出来后 24 小时内对订单与处理结果提出异议；服务者不能拒绝受理，也不能自行恢复结算。

## 5 广场：论坛与需求协同

论坛承担交流、内容沉淀和服务发现，需求模块承担可匹配的服务意向。两者可以相互引导，但普通帖子不能直接生成接单或结算义务。

### 论坛功能结构

| 模块 | 首期功能 |
| --- | --- |
| 浏览与分发 | 推荐、最新、板块、话题、搜索；建议板块包括游戏交流、语音话题、学习打卡、经验反馈和平台公告。 |
| 内容创作 | 图文发帖、编辑草稿、发布前校验、我的帖子；显示审核中、已发布、需修改或未通过及原因。 |
| 互动关系 | 帖子详情、回复、点赞、收藏和关注；互动通知进入消息中心，公开资料可关联服务者主页。 |
| 内容治理 | 举报、原因选择、证据补充、整改后重提、申诉进度；后台支持板块管理、审核、置顶、推荐与处罚。 |

### 发帖权限和会员关系

| 行为 | 普通用户 | 月度 VIP | 认证服务者 |
| --- | --- | --- | --- |
| 浏览论坛与购买服务 | 允许 | 允许 | 保留用户功能，允许 |
| 发帖和回复 | 按现行方案不开放 | 允许且需内容审核 | 仍按账号 VIP 权益判断 |
| 结构化或匿名需求 | 按现行方案不开放 | 允许且需需求审核 | 仍按账号 VIP 权益判断 |
| 应征公开需求 | 不允许 | 无服务者认证则不允许 | 通过认证并满足接单条件 |

若希望通过普通用户发帖扩大社区参与，可将“普通用户开放基础图文发帖”作为后续商业规则调整；这会改变原会员权益，需单独确定，当前建议稿不默认开放。

### 从帖子到服务需求

帖子详情可提供“转为服务需求”。用户必须具备需求发布权限，补齐服务类型、预算、时间、语言、服务区间等结构化字段，并通过需求审核后才进入匹配。帖子回复和私聊中的口头约定不直接替代平台订单。

匿名需求只向普通浏览者隐藏发布身份，平台授权岗位仍可追溯账号、订单和证据来源。代理仅可在指定工作项内收取材料和升级问题，不获得论坛全量内容审核或匿名来源查询权限。

## 6 运营后台 总控与代理

运营后台共用登录、工作项、权限和审计能力。总控负责平台业务闭环，代理只承接已分配的协助工作。总控内部仍按申请、复核、执行分岗，不能因名称为“总控”就让同一岗位包办所有敏感动作。

| 总控业务域 | 主要职责 |
| --- | --- |
| 工作台 | 平台待办、风险提醒、异常订单、工作项详情和超时升级。 |
| 用户与会员 | 用户列表详情、会员列表详情、权益及状态查询。 |
| 服务者与商品 | 入驻审核、KYC 结果引用、技能和商品审核、服务者状态。 |
| 论坛内容与需求 | 板块及帖子治理、需求审核、审核原因和申诉协作。 |
| 匹配与派工 | 匹配异常处理、工作项分配与升级；保留无匹配和候选失效处理。 |
| 订单履约与售后 | 订单详情、履约节点、中止申请（处理方式设置、处理人、24 小时时限、异议期、复核）、售后案件。 |
| 财务与结算 | 余额钱包与数字货币充值提现、支付退款、周期结算与推广分红日结、Ledger 只读、四方对账、批次出款和财务执行。 |
| 风控与申诉 | 举报、风险案件、处罚恢复、独立申诉复核及关联风险。 |
| 系统与权限审计 | 国家城市、语言、角色与数据权限、通知模板、审计日志。 |

### 代理工作台与六项动作

代理导航保留“工作台、服务者协助、需求协助、订单协助、我的权限”。服务者协助处理材料完整性和通知补件；需求及订单协助处理匹配异常、订单异常和售后材料。具体动作限于以下六项：

1. 查看本人授权范围。
2. 查看系统分配给本人的工作项。
3. 补充处理记录。
4. 上传平台指定材料。
5. 提交升级申请。
6. 标记本人协助完成。

代理不能领取或抢单、转派、终审、修改需求或订单状态、冻结解冻资金、退款放款、处罚账号或导出数据。“协助完成”只更新本人工作项，不代表订单完成、案件结案或审核通过。

### 代理商业关系的后续定义

“代理”在首期代表受限运营协助角色。招募服务者、团队绑定、渠道归属和佣金是可选商业模块，需要另定授权与结算规则；不能因改名为代理就默认开放。若启用，由平台维护比例、归属、有效期及撤销，代理仅查看本人的授权范围。

## 7 服务期与周期结算

会员下单时选择服务期和结算周期，一次付清整个服务期的费用；服务者的收入按结算周期到期自动结算。平台向服务者出款仍按日或按周批次处理，出款批次与结算周期分别配置。

| 维度 | 规则 |
| --- | --- |
| 服务期 | 单次服务为 1 次；按天商品可选 1 / 3 / 7 / 14 天；按周商品可选 1 / 2 周。可选档位由运营配置，并受服务者已开放的档期限制。 |
| 结算周期 | 每 1 / 3 / 7 天结算一次，不能长于服务期；单次服务在服务当天结束后结算。 |
| 付款 | 下单时一次付清整个服务期的费用，资金进入平台托管（待履约）；不再按期预付当期费用。 |
| 续费 | 服务期结束后如需继续，重新下单；自动续费为后续独立能力。 |
| 自动结算 | 每个结算周期结束后次日 00:00（业务时区）自动结算：周期内未申请中止即视为合格，会员也可提前确认完成。结算后按成交时的分账快照计入服务者、代理、分站、公会的可结算收入。 |
| 开始前取消 | 首次服务开始前（按服务规则提前的小时数，例如 2 小时）可取消订单，全部费用退回余额钱包并释放档期。 |
| 开始后中止 | 合作正常时不能无故取消；服务不达标时可申请中止，退还尚未结算的费用（第 9 节）。 |
| 服务额度 | 每期明确每日次数或时长、内容范围、预约规则，不能解释为全天无限陪伴。 |
| 时间口径 | 展示业务时区、服务起止日期和各结算周期的结算时间；与平台出款批次时区分开。 |
| 服务者出款 | 已结算的收入进入可结算余额，按日或按周批次出款，或由服务者申请提现，须满足资金与账户条件。 |

### 主订单 服务期 周期账单 履约记录

主订单保存用户、服务者、商品规则、服务期与结算周期、总服务关系和试聊换人权益。周期账单保存每期（每个服务日或服务周）的应付、已付、服务范围、退款及结算分配；一个结算周期由若干服务日组成。履约记录保存每日或每次到场、实际服务、完成摘要、确认和异议。

结算周期到期时，按周期内的履约金额结算。对于按整期目标验收、不可拆分的服务，结算周期应等于服务期，到期整体验收后再结算，不能机械地平均拆分放款。

### 交易成功与确认

支付成功只表示收款，不等于交易成功。每个结算周期结束且未申请中止，按预先公示的规则视为该周期服务已确认；会员也可以提前确认。有争议的部分进入中止申请流程并暂停结算，无争议的周期依规则结算。

会员提交中止申请后，申请当天起的服务暂停，尚未结算的费用全部暂停结算；已经结算的周期不受影响。处理期间，订单内的提交履约、确认、改期等操作暂停。

### 示例 每天100元 连续7天 每3天结算一次

| 项目 | 说明性金额或状态 |
| --- | --- |
| 下单一次付清 | 700 元（7 天 × 100 元），资金由平台托管；实际币种由上线市场确定。 |
| 第 1 期（第 1—3 天） | 第 4 天 00:00 自动结算 300 元。 |
| 第 2 期（第 4—6 天） | 第 7 天 00:00 自动结算 300 元。 |
| 第 3 期（第 7 天） | 第 8 天 00:00 自动结算 100 元。 |
| 第 5 天申请中止 | 已结算的第 1 期不变；尚未结算的 400 元暂停结算，按处理结果全部或部分退回会员余额钱包，其余结算给服务者。 |

## 8 平台收款、余额钱包与出款

资金路径为：会员以数字货币充值到余额钱包 → 下单一次付清，资金进入平台托管（待履约）→ 结算周期到期自动结算为服务者可结算收入 → 满足清算、异议及账户认证条件后，日或周批次出款 → 支付商确认打款成功。平台不能把未结算款或中止处理中的款项作为可出款收益。

### 会员余额钱包（V1.2 新增）

| 项目 | 规则 |
| --- | --- |
| 计价 | 以 USDT 计价。首期商品也以 USDT 定价，不需要换算；以后启用其他定价币种时，订单按支付时的汇率折算并保存（见第 12 节）。 |
| 充值 | 生成充值订单和收款地址；到账、失败或结果未知（只能查询原请求）；同一笔到账只记一次。 |
| 余额构成 | 充值余额：充值本金，只能用于消费（后台可配置是否允许提现，默认不允许）。可提现余额：推广分红、订单退款。 |
| 余额支付 | 先扣充值余额，再扣可提现余额；余额不足时引导充值后返回继续支付。 |
| 退款入账 | 订单退款退回余额钱包，按原扣款比例回到充值余额与可提现余额。 |
| 提现 | 只能提取可提现余额；申请后冻结 → 平台审核 → 出款 → 查询结果。结果未知只查询原请求，不重复出款；最低提现金额与手续费由后台配置。 |
| 不支持 | 会员之间转账。服务者收益仍按收益结算与提现流程处理，不进入会员余额钱包。 |

### 收益计算与对账

逐笔保存用户实付、平台服务费、支付费用、税费、退款扣减及服务者净收入，并关联订单和费率规则版本。当前不预设费率；代理佣金若启用，应另外明确从平台收入支付还是按约定单独扣除。

保留订单、PSP 支付商、Ledger 账务、Payout 出款四方对账，余额钱包流水纳入账务核对。订单、支付、履约、退款、暂停结算和出款状态分别维护；出款处理中或结果未知时先查询原请求，确认可重试后再处理，避免重复支付。

### 退款与出款失败

尚未结算的金额先暂停结算并核减，再按处理结果退回会员余额钱包。已结算并付给服务者的金额，如需退还，进入售后追偿、按协议后续抵扣或平台承担流程，不能假定支付商能够自动撤回。失败出款回到可重试或人工处理状态，原占用金额须与查询结果同步释放或继续保留。

日结或周结表示平台处理批次，不等于固定到账时刻；支付商清算、节假日和异常处理都可能影响到账。

### 支付接入前必须明确的能力

收付仅接 USD 数字货币。接入前须由持牌数字货币支付服务商确认：业务准入、具体代币与网络（如 TRC20 / ERC20）、充值地址或支付单、回调签名、按商户单号查询、出款与提现、地址风险筛查及对账文件。未确认前，相关资金功能不能上线。

## 9 中止申请与处理

服务开始后，如果服务不达标，会员可以从订单详情申请中止，退还尚未结算的费用。合作正常时不能无故取消；服务开始前请直接取消订单（全额退回余额）。提交申请不等于退款获批，也不能单方面抹除已经结算的服务费用。

### 申请

申请须选择不达标原因：服务者迟到或缺席、服务内容与约定不符、服务态度或言行问题、其他服务质量问题。同时填写至少 10 字的具体情况，可上传最多 3 张图片，并确认情况属实。

提交后，申请当天起的服务暂停，尚未结算的费用全部暂停结算。同一订单同时只能有一个处理中的申请。有处理结果之前会员可以撤回，服务随即恢复。

### 处理方式（后台设置）

| 设置 | 处理路径 |
| --- | --- |
| 直接由平台处理（默认） | 所有申请都直接由平台处理，不经过公会。 |
| 先由公会处理 | 服务者签约公会时，先由公会在 24 小时内处理；公会超时未处理，自动转平台。服务者未签约公会时，直接由平台处理。 |

默认值“直接由平台处理”已于 2026-10-06 确认。设置由总站在运营后台“服务中止与争议”中修改，须填写调整依据；只对之后提交的申请生效，每个申请保存提交时的处理方式。

### 处理流程与时限

| 环节 | 规则 |
| --- | --- |
| 公会处理 | 仅在“先由公会处理”且服务者签约公会时出现。24 小时内作出处理结果，超时自动转平台。 |
| 平台处理 | 平台售后人员领取后处理，记录处理人；24 小时内作出处理结果，超时标记并升级至平台主管。 |
| 异议期 | 每次处理结果出来后 24 小时内：会员可以申诉（对公会结果转平台处理，对平台结果转平台复核）；服务者可以对订单与处理结果提出异议并提供材料。期满无人提出异议则执行。 |
| 平台复核 | 对平台处理结果的申诉或异议由平台复核，24 小时内完成；复核结果为最终结果，提交后立即执行。 |
| 双方材料 | 处理过程中，会员可补充材料，服务者可提交说明与图片。 |

### 处理结果与执行

结果一：退还全部尚未结算的费用，服务终止。结果二：部分退款，其余尚未结算的部分结算给服务者，服务终止。结果三：驳回申请（合作正常），解除暂停，服务继续，期间到期的周期在下一次 00:00 照常结算。

退款退回会员余额钱包。执行结果和全部处理记录（处理人、依据、时间）留存审计。申请状态与资金状态分别维护，例如订单已中止，但部分未结算费用仍需结算给服务者。

### 已结算款项的追偿（沿用 V1.1）

已经结算的周期不在本流程的退款范围。如平台另行认定需要退还已结算款项，按出款阶段处理：

| 出款阶段 | 可执行动作与限制 |
| --- | --- |
| 尚未提交支付渠道 | 将涉及的可拦截金额拆出待出款批次并保全，出款前再次检查保全状态。 |
| 已提交渠道 在途或结果未知 | 尝试撤销或请求拦截，并查询支付商结果；不承诺止付成功，也不重复发起出款。 |
| 已到账 | 进入售后追偿、按协议后续抵扣或平台承担流程，不能直接按未付款余额冻结或假定自动撤回。 |

### 新增页面与岗位边界

- **用户中心：**申请入口、申请表（原因、说明、图片）、进度、当前处理人与时限、处理结果、申诉入口。
- **服务者中心：**中止提示、说明与图片提交、异议入口。
- **公会中心：**“售后处理”页签；仅在“先由公会处理”时出现待处理申请。
- **运营后台：**“服务中止与争议”，包括处理方式设置、申请列表与详情、领取处理、处理与复核、时限与升级。

同一账号依据本人在该订单中的购买或服务关系使用相应功能。代理只收材料与升级，不冻结解冻资金，不处理申请。

### 多语言

2026-10-13 补充：用户资料中的服务语言按 IP 所在地区自动切换，中文地区为简体中文，其他地区为英语；只用本站已发布语言，识别失败或语言未开放时使用分站默认。界面语言仍独立选择，服务者的可服务语言仍由本人申报。头像选择列表不显示编号，仍可筛选、预览、上传并保存。三端顶部预览工具栏及资料弹窗可查看“修改说明”，每次修改同步更新关联文档，详见 [最新修改说明](修改说明.md)。

| 项目 | 规则 |
| --- | --- |
| 语言管理 | 首期只启用简体中文与英语（前端使用 i18n 框架 i18next）。原型另预置繁体中文、日语、泰语、越南语、马来语、菲律宾语、阿拉伯语作为草稿，补齐译文并按 D01 确认后启用，不需要改代码。记录文字方向，预留阿拉伯语等右向左语言的整体镜像。中文是原文与兜底语言，不能停用。 |
| 分站配置 | 每个分站可继承平台，或独立设置开放语言、默认语言、备用语言、展示时区、时间与日期格式、是否自动识别浏览器语言、是否允许用户切换。 |
| 翻译范围 | 界面文字、业务内容（商品名称与规格、购买规则、服务模板、会员说明、站点介绍、论坛板块）、通知模板。用户发布的帖子、资料、消息、证据不翻译。 |
| 质量控制 | 中文原文更新后，旧译文标记为“原文已更新”；译文中的变量必须与原文一致；交易说明、价格说明等必要内容未完整翻译时，不能发布该语言。 |
| 发布 | 保存译文不会立即上线；发布前做完整性检查，发布后可以回滚到历史版本。 |
| 用户语言 | 按手动选择、账号偏好、浏览器偏好、分站默认语言的顺序确定；只能选择本站已发布的语言。切换语言不改变身份、站点、权益、订单币种与金额。服务者可提供服务的语言与界面语言分开设置。 |

### 多币种

| 项目 | 规则 |
| --- | --- |
| 首期 | 只用 USDT：商品定价、订单、支付、钱包、充值、提现、分账与分红都以 USDT 计价与结算，不需要换算。 |
| 多币种准备 | 订单、账单与资金记录保留定价币种与汇率快照字段；分站保留定价币种配置（首期都是 USDT）。以后启用其他币种不需要改结构。 |
| 汇率获取 | 后台“币种与汇率”每天自动获取一次其他币种对 USDT 的汇率，数据源与获取时间可配置，每次获取都保存版本。首期汇率只作参考，不参与计价。 |
| 获取失败 | 保留上一版本，在今日工作台提醒；总站手动录入汇率（须填写依据），也可以手动立即获取。 |
| 启用其他币种 | 按 D03 确认后启用；分站只能选择已启用且汇率当天有效的币种。支付时保存汇率快照，之后的结算、退款与分红按快照计算；资金记录保存双金额；报表按币种分别统计。 |
| 小数与舍入 | 每个币种定义小数位（如越南盾、日元 0 位），折算后按目标币种舍入。 |
