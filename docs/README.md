## 文档之间的关系

1. **产品规则：**以《两端产品架构建议稿》和模块文档为准。两者冲突时以模块文档为准，并同步修订建议稿。
2. **技术实现：**以《技术架构与技术选型》为准。
3. **参数：**以《待定参数与决策记录》为准。待定参数不得由研发或 AI 代填。
4. **交互细节：**以原型 V23 为准。

## 原型

- **文件：**`陪伴服务平台_三端交互原型.html`（与 `dist/index.html` 一致）。
- **使用说明：**`使用说明.txt`。
- **预览：**`python3 -m http.server 8000 --directory dist`，然后打开 `http://127.0.0.1:8000/`。
- **构建：**`python3 scripts/build-v23.py`。
- **业务检查：**
  - `node scripts/verify-v22.cjs`（26 组）
  - `node scripts/verify-mcn.cjs`（46 组）
  - `node scripts/verify-service.cjs`（11 组）
  - `node scripts/verify-intl.cjs`（8 组，多语言与多币种）
  - `node scripts/verify-gender.cjs`（25 组，性别联动、匹配、权限与兼容）
  - `node scripts/verify-demands.cjs`（15 组，需求贴冻结预算与多申请报价）
  - `node scripts/verify-reviews.cjs`（22 组，成交后双向互评）
  - `node scripts/verify-alignment.cjs`（15 组，用户端动作与后台页面对齐）
  - `node scripts/verify-ux.cjs`（7 组，帮助、设置、协议、订单详情、列表顺序、金额标签）
  - `node scripts/verify-feed.cjs`（11 组，首页轮播与后台配置、图文流、列表页图文卡片）
  - `node scripts/verify-images.cjs`（8 组，帖子图片上传、图片审核与后台开关）
  - `node scripts/verify-cards.cjs`（8 组，订单卡片与记录行、用户端不显示分站、中文地点与时区、USDT 标签）
  - `node scripts/verify-avatars.cjs`（8 组，默认头像选择、上传头像与图片审核）
- **浏览器检查（需本机 Chrome 与 playwright-core）：**`node scripts/ux-check.cjs <地址> pc|h5`（9 步）、`node scripts/feed-check.cjs <地址> pc|h5`（8 步）、`node scripts/images-check.cjs <地址> pc|h5`（7 步）、`node scripts/cards-check.cjs <地址> pc|h5`（PC 5 步 / H5 6 步）、`node scripts/avatars-check.cjs <地址> pc|h5`（5 步）、`node scripts/ui-check-v23.cjs <地址> pc|h5`（20 步）。前后对比截图见 `artifacts/ux/index.html`。

性别字段在 01 定义，选人与匹配在 03 引用，公会 / 代理 / 推广关联在 06 引用，统计与说明在 07 引用；原型操作步骤见 `使用说明.txt`“六之六”。正式后端接口均为待实施建议，本轮没有新增真实 API。

## 维护约定

- 修改规则时，先改模块文档（规则编号不复用），再改原型或代码，最后更新检查清单。
- 新的决策写入《待定参数与决策记录》，注明日期与来源。
- 本目录不保留旧版本；需要回溯时使用版本控制。
