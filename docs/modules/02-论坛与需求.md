## 1 目标与范围

用户端一级导航为“首页、发现、广场、消息、我的”。本模块负责以下内容：

- **广场（需求与社区）：**帖子与需求。
- **立即找人、下单前咨询、关注与常约、组队房、陪伴活动。**

“发现”是按条件找服务者，属于 03 模块。

| 首期包含 | 后置 |
| --- | --- |
| 板块话题、帖子回复、点赞收藏关注、内容审核与举报、社区交流帖（申请后开放双方会话）、结构化 / 匿名需求与审核、立即找人匹配、下单前咨询、关注与上线提醒、免费主题组队房、主题活动 | 普通用户基础发帖（D06）、发帖押金（待定）、推荐算法、礼物与打赏（明确不做） |

| --- | --- | --- | --- |
| 浏览广场、活动与房间摘要 | 允许 | 允许 | 允许 |
| 发帖、回复、需求发布、咨询、关注、立即找人、组队房互动 | 不允许 | 允许（帖子与需求需审核） | 按本人 VIP 判断 |

| 后台审核、关闭房间、发布活动 | 总站 | — | — |

站长只能查看本站记录并提交协助；代理只能处理分配给他的工作项中的材料。

## 5 主流程

1. **发帖：**VIP 用户编写帖子 → 发布前校验 → 审核中 → 已发布 / 需修改 / 未通过。可以举报，整改后重新提交。
2. **社区交流：**作者发布交流帖 → 他人申请交流 → 作者接受 → 开放仅双方可见的会话 → 任一方可结束，保留历史。
3. **需求：**发布结构化或匿名需求 → 需求审核 → 匹配候选 → 用户选人 → 生成待支付订单（见 04）。
   - 帖子可“转为服务需求”，补齐结构化字段后进入审核。
4. **立即找人：**选择服务、预算、日期、时段、游戏或话题、语言 → 搜索中 → 候选响应 → 用户选定 → 确认预约 → 待支付 → 已预约。
5. **咨询：**用户在服务者主页点“先咨询” → 复用同一用户、服务者、站点下进行中的咨询 → 双方消息与服务卡 → 任一方结束后只读。
   - 服务卡实时读取当前价格、币种与资格。
6. **组队房：**VIP 创建或加入 → 申请上麦 → 房主同意 → 禁言、移出、下麦、留言、邀请；房主退出或后台关闭后只读。
7. **活动：**总站编辑草稿 → 预览 → 填写依据后发布 → 下架。编辑已发布的活动会回到草稿状态。

## 6 状态机

| 对象 | 状态与迁移 |
| --- | --- |
| 帖子 / 需求 | 草稿 → 审核中 → 已发布 / 需修改（→ 审核中）/ 未通过；已发布 → 已下架（处罚） |
| 匹配 | 搜索中 → 有候选 → 已选定 → 待付款 → 已预约；另有已取消、已超时、无结果、候选已失效、服务者拒绝 |
| 咨询 | 进行中 → 已结束（只读，之后可以新开咨询） |
| 房间 | 开放 → 已关闭（房主退出或后台关闭）；成员：在房 / 在麦 / 被移出 / 已退出 |
| 活动 | 草稿 → 已发布 → 已下架；阶段由运营明确设置 |

## 7 业务规则

- `CM-R001` 发帖、回复、需求发布须有效 VIP，且需审核；普通用户可以浏览和直接购买。
- `CM-R002` 普通帖子和私聊约定不能直接生成接单或结算义务。帖子转需求时，须补齐结构化字段并通过审核。
- `CM-R003` 匿名只对普通浏览者隐藏发布身份，授权岗位仍可追溯。
- `CM-R004` 社交互动（申请、接受、发送）须有效 VIP；查看历史、拒绝、撤回、结束和举报不需要续 VIP。
- `CM-R005` 咨询在同一用户、服务者、站点下复用；非参与人不能读写；拉黑后禁止新咨询、新消息和新匹配。
- `CM-R006` 重复提交进行中的匹配会复用原记录；选定候选不扣款。服务者离线、暂停、到期、被拉黑或档期被占用时不能选定。
- `CM-R007` 匹配等待时间可配置；超时、无结果、候选失效都有明确结果。后台人工推荐的候选仍需服务者响应和用户本人选定。
- `CM-R008` 组队房最多 8 人、4 个有效麦位；房主退出即关闭；后台关闭后只读并展示依据；VIP 到期的成员只能收尾（查看、退出、下麦、举报）。
- `CM-R009` 组队房和活动不收费，不做礼物、打赏、红包或奖金。
- `CM-R010` 跨分站的咨询和入房会被拒绝。
- `CM-R011` 关注后可以开关上线提醒；取消关注和关闭提醒不需要 VIP。
- `CM-R012` 用户发布的内容（帖子、回复、需求、咨询、消息）保持原文，不自动翻译，界面翻译也不改写这些内容；板块名称、活动标题等运营内容可维护多语言（07）。
- `CM-R013` 需求预算与匹配预算按本站定价币种（首期 USDT）填写和展示；生成订单时按 04 模块的币种与汇率规则计价。立即找人可以按服务语言筛选候选。

## 8 异常与边界

- 筛选无结果时可清空条件；预算过低提示无结果。
- 人数或麦位已满、被移出、被拉黑、房间已关闭时，相应动作被拒绝。
- 存储失败时回滚本次操作，保留旧数据。

## 9 资金与证据影响

- 本模块不直接产生资金。匹配选定后生成待支付订单，转入 04 模块。
- 举报证据进入 05 模块的举报与风险流程；运营后台只看咨询索引和消息数量，不批量查看正文。
